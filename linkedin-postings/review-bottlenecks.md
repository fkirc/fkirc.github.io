Agents made writing code cheap. They did not (yet) make reviewing it cheap. Review has often leaned on cheap signals: is it well-structured, does it read competently. Those signals were used in the past because producing polished-looking code required real effort. Agents break those signals.

So what happens when our agentic verification is not strong enough yet? Then the question of who should do a task tends to collapse into fiduciary trust: who do I trust to be rigorously skeptical on my behalf. That is expensive, it does not scale, and it quietly punishes anyone who changes jobs or joins a new team.

So, the metric worth optimizing is not raw output. It is how much effort a result costs to review. And surprisingly, using agents to generate trust-chains is still heavily underused. To address the review bottleneck, the power of agents should be unleashed for agentic verifications, instead of relying overly on selective personal trust or outdated test mechanisms.
