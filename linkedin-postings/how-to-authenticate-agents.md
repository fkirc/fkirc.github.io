How to authenticate agents: Is OAuth the new king?
Every company that exposes a new MCP needs to think about authentication. One way to do it is "manually" configured API-keys. Easy to implement, but in many cases not optimal for the UX. So here comes OAuth into the scene: Connect an agent to an MCP, and then "authorize" it via a slick and easy-to-use OAuth-web-page. But the devil is in the detail: Which sub-flavor of OAuth should we use? "Static OAuth" is probably not viable, because the market-demands are shifting every month, so whatever "static OAuth" gets configured is probably already outdated on day 1 of the release. Then there is "OAuth-DCR", which is more dynamic, but also more fragile. To reduce security-risks, this part of the stack should be as robust and simple as possible. Enter "OAuth-CIMD": It seems that "OAuth-CIMD" with a whitelisting combines the best of both worlds: A reduced attack-surface, and the ability to easily expand a whitelist. Hence, "OAuth-CIMD" might be on its way to becoming a widely used standard in agentic authentication.
