MCP is nowadays a must-have for many public-APIs. A logical evolution: Agents can connect rapidly to MCP, without wasting many tokens on docs-ingestion. But how to build an efficient and snappy MCP? Creating a 1:1 conversion from REST to MCP does not always yield an efficient result. The optimization-metrics are different. For example, in REST, an unused property can be slopped in without much damage, but in MCP an unused property might already create an agent-confusion in the worst case. Also, the queries of "foreign keys" are sometimes cheaper in REST than in MCP. The "unrolling" of foreign keys can make MCPs faster under certain conditions. A brilliant point from Brian Cheong: An MCP should match the decisions an agent needs to make, with just enough context to make them safely. So my takeaway is clear: Let us try to build MCPs from an agent-first-mindset, instead of being too married to the patterns of any pre-existing REST APIs.
